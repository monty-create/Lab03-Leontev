# Практическая работа №3. Представление данных: как числа и текст превращаются в байты

## Цель работы
Изучить бинарное представление целых чисел и текстовых строк в памяти ПК, исследовать порядок байтов Little-Endian и работу кодировки UTF-8.

## Оформление результатов исследований

### 1. Представление числа в байтах
При запуске тестов для разных значений int32 (занимает 4 байта) получились следующие байтовые массивы:
- Число **1**: `01-00-00-00`
- Число **256**: `00-01-00-00`
- Число **65536**: `00-00-01-00`

**Закономерность:** 
Так как компьютер работает в порядке Little-Endian, младший значащий байт записывается первым. При увеличении числа заполняются следующие ячейки памяти слева направо. Для числа 256 значение переходит во второй байт (так как один байт вмещает только до 255), а для 65536 — в третий байт.

### 2. Порядок байтов
- **Значение BitConverter.IsLittleEndian:** `True`
- **Число для теста:** `305419896`
- **Его HEX-представление:** `0x12345678`
- **Получившиеся байты в памяти:** `78-56-34-12`

**Объяснение порядка байтов:**
Флаг True означает, что архитектура процессора использует порядок Little-Endian. Из-за этого байты переворачиваются: самый младший байт числа (`78`) ложится в самую первую (младшую) ячейку памяти, а самый старший байт (`12`) — в последнюю.

### 3. Текст и UTF-8
- Строка `"ABC"`: 3 символа, в памяти занимает **3 байта** (`41-42-43`).
- Строка `"Привет"`: 6 символов, в памяти занимает **12 байтов** (`D0-9F-D1-80-D0-B8-D0-B2-D0-B5-D1-82`).

**Вывод:**
Для английского текста один символ строго равен одному байту (код совпадает с ASCII). Для кириллицы в UTF-8 на каждую русскую букву выделяется строго по 2 байта, поэтому размер в байтах стал в два раза больше количества букв.

### 4. Английская и русская буква
- Строка `string english = "A"` -> Получился байт: `41` (1 байт).
- Строка `string russian = "А"` -> Получились байты: `D0-90` (2 байта).

**Объяснение разницы:**
В кодировке UTF-8 символы первой половины таблицы латиницы кодируются одним байтом для экономии места. Национальные алфавиты (включая русский) находятся дальше по таблице символов Юникода, поэтому под них динамически выделяется по 2 байта. Один и тот же визуальный символ "А" имеет абсолютно разную структуру в памяти.

### 5. Обратное преобразование
- Строку можно превратить в байты через `Encoding.UTF8.GetBytes()` и восстановить без потерь обратно через `Encoding.UTF8.GetString()`.
- Число переводится в массив байтов через `BitConverter.GetBytes()` и восстанавливается обратно функцией `BitConverter.ToInt32()`. При обратном пути данные полностью совпадают с исходными.

## Ответы на контрольные вопросы

1. **Что такое байт и сколько бит содержит один байт?**
   Байт — это минимальная единица хранения данных, к которой компьютер может обратиться напрямую по адресу памяти. Один байт состоит строго из 8 бит и может хранить число от 0 до 255.
2. **Почему int занимает несколько байтов?**
   Потому что стандартный тип int (int32) хранит большие числа (до 2 миллиардов). Одного байта (максимум 255) для этого физически не хватит, поэтому под int выделяется 4 байта (32 бита).
3. **Что показывает BitConverter.GetBytes()?**
   Метод принимает переменную (например, int или long) и разбивает её на массив отдельных байтов в том виде, в каком они физически будут записаны в ОЗУ.
4. **Что означает BitConverter.IsLittleEndian?**
   Этот флаг показывает порядок байтов процессора. Значение True означает, что на данном ПК младшие байты записываются в память первыми (порядок от младшего к старшему).
5. **Почему порядок байтов может отличаться от привычной записи числа?**
   Потому что люди записывают числа в порядке Big-Endian (от старшего к младшему, как `12 34`), а большинство современных процессоров x86/x64 эффективнее работают в порядке Little-Endian, записывая байты задом наперед (`34 12`).
6. **Почему количество символов строки не всегда равно количеству байтов?**
   Потому что UTF-8 — это кодировка с переменным размером символа. Английские буквы занимают по 1 байту, русские — по 2 байта, а некоторые спецсимволы и эмодзи могут занимать до 4 байтов.
7. **Что делает Encoding.UTF8.GetBytes()?**
   Переводит текстовую строку в массив байтов, кодируя каждый символ по международному стандарту UTF-8.
8. **Зачем для обратного преобразования текста используется Encoding.UTF8.GetString()?**
   Чтобы программа правильно расшифровала байты. Она должна знать алгоритм (кодировку), по которому текст превращали в цифры, иначе вместо букв получится нечитаемый мусор.
9. **Почему одни и те же байты могут интерпретироваться по-разному?**
   Потому что сами по себе байты в памяти не имеют цвета или смысла. Это просто цифры. Смысл появляется только тогда, когда программа решает, как их читать — как кусок числа или как буквы по таблице кодировки.
10. **Чем представление числа в памяти отличается от представления текста?**
    Число переводится в байты целиком по математическим правилам бинарной системы (целиком весь int). Текст переводится посимвольно — каждый знак строки кодируется отдельно по таблице кодировки независимо от соседних букв.

## Итоговый вывод (Ответ на проблемный вопрос)
Если от другой программы получены байты `48 65 6C 6C 6F`, то определить их точный смысл без правил интерпретации невозможно. Они могут быть частью большого бинарного числа, куском файла или словом "Hello" в UTF-8. Просто увидеть последовательность байтов мало — программа обязана заранее знать жесткие правила и контекст, по которым эти данные должны расшифровываться.
